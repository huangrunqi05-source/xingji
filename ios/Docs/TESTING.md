# 验收方案

## 本机可以验证的部分

运行 `Scripts/check.sh`。Swift Package 实际编译 Core 与 Data，命令行使用真实 Core Data 内存/SQLite 存储及 ImageIO 编码器；没有模拟云端权限验证结果。

检查覆盖路过/停留、采样缺口、商场歧义、坐标系、定位跳变、乱序、轨迹分块、评分、模式切换、去重、忽略半径、共享字段最小化、中国日期、GPX、ZIP CRC/中文路径、照片 GPS/拍摄时间移除和尺寸缩小、SQLite 更新与重开、共享对象关系隔离、只读入口与全量删除。

`swift test` 需要完整 Xcode 的 XCTest。Command Line Tools 缺 XCTest 时，用命令行验证运行核心场景，不声称 XCTest 已执行。

## 真机：地图与定位

至少使用两款 iPhone、两种受支持 iOS 系统版本，记录设备型号、系统、App build、网络和电池健康。

1. 全新安装不同意用途说明：不创建高德搜索/地图实例、不启动定位、不初始化 CloudKit 同步。接受说明仍默认关闭记录。
2. 依次测试不授权、仅使用期间、始终允许、关闭精确定位。界面真实反映受限状态，撤权后停止接受新位置并切断路线。
3. 走过门店不停留、两分钟短暂停留、十分钟到店、连续两家店、当天再次到访。通过手工时间记录核对，不得将路过当成可靠到访。
4. 商场楼层、相邻餐厅、同名分店、咖啡店及零售店。确认列表允许选择/重新搜索；用户更正期间的在途搜索不能覆盖手动编辑。
5. 先按原始 GPS 识别后忽略；再手动选择 GCJ-02 店铺后忽略，两种情况下都要验证同地点不会再次进入候选。
6. 旅游模式静止十分钟后离开，应通过系统到访或稳定样本识别。记录暂停→移动→恢复、中途切后台、锁屏、系统定位失败、强制结束后重开；不能跨间断画直线。
7. 室外至少核对五个已知店铺，确保地图标记与真实位置吻合；检查 GPX 为 WGS84，地图仅转换一次。
8. 无网络：定位结果先落本机，查询失败保留待确认；恢复网络后可重试，不重复创建记录。
9. 录制一个完整日常日与一个旅游日，对比同设备未启用 App 的基线耗电。记录时长、起止电量、温度/发热描述、轨迹覆盖、误判和遗漏。未得到数据前不宣称省电百分比或准确率。

## 双账号：CloudKit 与只读共享

准备两个不同 iCloud 账号 A/B，至少两台真机。

1. A 新建记录含照片，另一台 A 设备同步；断网编辑/删除后恢复，核对照片、评分和同一 UUID 不重复显示。
2. 测试 iCloud 未登录、空间不足、网络中断、账号切换；本地仍可查看，界面不把失败说成已同步。特别核对不同账号切换后的数据边界。
3. A 创建清单，加一条记录并邀请 B。B 只看到预览内容；查看 CloudKit 记录图，不应出现 PrivateRecord、PhotoBlob、路线对象或精确时刻。
4. B 端不显示编辑/删除条目功能；使用测试构建主动尝试写入 shared database，确认服务器拒绝，而不仅是 UI 隐藏。
5. A 修改私人记录：B 不应改变。A 主动“从私人记录更新”并确认预览：B 更新一次，旧版本移除。
6. A 继续加记录，B 能收到；删除原记录撤回副本；移除 B 后，确认 B 后续服务端读取失败、共享列表同步移除。
7. 邀请冷启动/热启动/首次安装后接受、首次用途说明前收到邀请、失效邀请、取消分享、退出清单。
8. A 撤销或 B 退出不会删除 A 私人到访/轨迹。删除所有数据在断网时不应显示全部成功；恢复后重试。
9. 重复以上关键流程于 **TestFlight + 生产 CloudKit schema**，开发环境成功不足以替代。

## 编辑与导出

- 到达晚于离开、非法评分被拒绝；清除评分不产生零分。
- 选择/移除/取消照片编辑、读取失败、照片达到上限；照片保留正确方向且无 GPS/原始拍摄时刻元数据。
- 检查导出 JSON 的图片引用、实际图片、每段 GPX 和中文 ZIP 文件名。不能导出 GCJ-02 点作为 GPS。
- 删除到访、删除旅行、删除清单、删除全部各自执行对应范围；只读清单只能退出。
- VoiceOver、最大动态字体、深色模式、小屏手机、键盘遮挡和空数据状态人工检查。
